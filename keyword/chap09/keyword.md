- 서버
    - 서버란 무엇인가요?
        - 네트워크를 통해 사용자에게 정보나 서비스를 제공하는 프로그램 또는 장치를 말한다.
    - 서버는 어떤 역할을 수행하나요?
        - 말 그대로 사용자의 요청을 받아 서비스를 제공하는 역할로 데이터를 저장하고, 가공, 정보 전달 등을 한다.
- 서버와 클라이언트
    - 서버와 클라이언트는 일반적으로 1:1, 1:N, N:M 관계 중 어떤 관계를 가지고 있을까요?
        - 위의 문장의 답을 찾고, 아래 문장을 완성해보세요.
            - 서버는  다수의 클라이언트가 접근한다.
            - 서버와 클라이언트는 일반적으로 일대다 관계를 가진다.
    - 서버와 클라이언트의 통신 구조를 식당 예시와 연결하여 정리하고 스터디에서 본인이 정리한 예시를 공유해 보세요.
    (식당에는 손님, 점원, 주방장, 냉장고가 있습니다.)
        - 클라이언트는 손님이다.
        - API는 점원으로 클라이언트의 주문을 받아 주방장에게 전달하고, 요리를 손님에게 전달한다.
        - 서버는 주방장으로 요청이 들어오면 냉장고에서 재료를 꺼내 요리를 한다.
        - 데이터베이스는 냉장고로 요리에 필요한 데이터를 보관하는 곳이다.
- 서버와 클라이언트 간의 통신
    - 서버와 클라이언트가 정보를 주고 받으려면 먼저 어떤 일을 해야할까요?
        - 네트워크 연결: 클라이언트와 서버가 네트워크를 통해 서로 연결한다.(IP주소와 포트 번호)
- 서버와 클라이언트 간의 통신 방식 - HTTP Protocol
    - HTTP Protocol에서 정보를 주고받기 위한 중요한 구성요소 2가지는 무엇일까요?
        - 요청
            - 메서드: 작업 종류 지정(GET, POST, PUT, DELETE)
            - URL: 요청 대상 리소스 위치 지정
            - 헤더: 요청의 메타데이터를 포함 (인증 정보, 콘텐츠 유형 등)
            - 본문(body): POST, PUT 요청에서 데이터를 포함
        - 응답
            - 상태 코드: 요청의 처리 결과 (200: OK, 404: Not Found 등)
            - 헤더: 응답의 메타 데이터 포함
            - 본문: 요청에 대한 실제 데이터 포함 (JSON)
    - HTTP 통신은 연결을 계속 유지하고 있을까요? 유지한다면 어떻게 유지할 수 있는지, 유지할 수 없다면 왜 유지할 수 없는지 찾아보세요. (Hint: State)
        - 기본적으로 연결을 유지하지 않는다.
            - 서버는 기본적으로 클라이언트의 상태를 보존하지 않는다.
            - 무상태(stateless) 환경에서는 회원 정보를 서버가 아닌 클라이언트가 토큰 형태로 들고 있으면서, 서버와 통신할 때 실어 인증한다.
            - 물론 상태 유지도 가능하지만 중간에 서버 장애가 나면 클라이언트는 처음부터 다시 작업을 요청해야하는 불편함이 있다.
    - HTTP Protocol에서는 Method를 통해 어떤 동작을 하고싶은지 나타낼 수 있습니다.
    주요 Method 5가지는 무엇이 있을까요? (Hint: CRUD)
        - GET : 조회. Read 데이터를 서버에서 가져올 때 사용한다
        - POST : 등록. Create 데이터를 생성하거나 서버로 제출할 때 사용
        - PUT : 수정. Update 데이터 전체를 교체할 때 사용
        - PATCH : 수정. Update 데이터의 일부만 수정할 때 사용
        - DELETE : 삭제. Delete 데이터를 삭제할 때 사용
    - HTTPS란 무엇이고, HTTP와 어떤 차이가 있을까요?
        - HTTP: 데이터를 그대로 전송하여 해커가 중간에 가로채면 내용은 다 볼 수 있다
        - HTTPS: SSL/TLS 인증서를 이용해 데이터를 암호화하여 전송한다.
- API
    - API란 무엇일까요? (Restful API가 무엇인지도 함께 정리해 주세요.)
        - 프로그램들이 서로 상호작용하는 것을 돕는 매개체로 클라이언트와 서버를 연결한다.
    - RESTful API란?
        - REST란 자원을 이름으로 구분하고, 자원의 상태를 주고 받는 통신 아키텍처이다.
        - HTTP URI를 통해 자원을 명시하고 HTTP Method를 통해 자원에 대한 CRUD operation을 적용한다.
        - RESTful API란 REST의 원리를 따르는 API이다.
            - URI에 동사보다는 명사(소문자 사용)
            - 마지막에 / 포함 안하기
            - 행위는 포함 안하기 등이 있다.
- Android에서 HTTP 통신하기
    - Android에서 HTTP 통신을 위해서는 외부 라이브러리를 사용해야 편리하게 진행할 수 있습니다. 그 중 대표적인 라이브러리로는 Retrofit2가 있습니다. 이에 대해 간단히 조사해보고 정리해보세요.
        - 안드로이드용 Type-safe HTTP 클라이언트 라이브러리이다.
        - 복잡한 HTTP 연결 작업을 아주 간단한 인터페이스 형태로 변환해 준다.
        - 내부적으로 OkHttp를 사용하여, JSON 응답을 자바.코틀린 객체로 자동 변환하는 기능이 있다.
    - Retrofit2를 실제로 Android App 내에서 사용하기 위해서 만들어야 하는 요소 3가지는 무엇이 있을까요?
        - DTO (Data Transfer Object) 클래스
            - 서버가 보내주는 JSON 데이터 형식과 1:1 매칭되는 데이터 클래스
        - Interface (API 명세서)
            - GET, POST 등 어노테이션을 사용하여, 어떤 서버 주소로 어떤 요청을 보낼지 정의하는 인터페이스
        - Retrofit Instance (Client)
            - 실제 Retrofit 객체를 생성하고 Base URL 등을 담고 있는 클래스
